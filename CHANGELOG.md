# Changelog

All notable changes to **Tadah.MLIP** (the MLIP module — high-level training / predict / data-balance orchestration) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

> Note: the umbrella project that ships the `tadah` binary is also called **Tadah.MLIP**; its changelog lives at the umbrella repo root and aggregates across all modules. This file is the per-module log for the `MLIP/` library layer.

## [Unreleased]

### Fixed
- **A `TASK` line of a task file followed by no key line is a task** (the next line is another `TASK` line, the end of the file, or there are only blank and comment lines before it). `MLIPUserConfigParser::splitSections` dropped such a section, so its name was never checked (`TASK bogus` followed by `TASK train` ran the training and exited 0) and a keyless task never ran (a last `TASK predict` relying on the `DBFILE` and `POTENTIAL` above the first `TASK` line: exit 0, nothing predicted; a file whose only task was keyless was refused as having no `TASK` section). Every `TASK` section is now kept and checked, and a keyless one runs on the GLOBAL keys. A `TASK` section is told from the GLOBAL section by a flag instead of by its name, so `TASK global` is refused as an unknown task: at the start of a file it was taken for the GLOBAL section, and after another task it reached `TaskFactory`, which crashed (segmentation fault). Tests: `test_user_config_sections.cpp`.
- **A comment on a `TASK` line of a task file** (`TASK train   # first task`, `TASK predict<TAB># second`) is not part of the task name: `MLIPUserConfigParser` reads the name from the text before the `#`, as `CoreUserConfigParser` reads a key line. The words of the comment were joined to the name, so `tadah --task` stopped with `Unknown task section "TRAIN.#.first.task"`, and a `TASK` line with only a comment after `TASK` was reported as an unknown section instead of a `TASK` without a name. Test: `test_user_config_sections.cpp`.

## [1.6.0] — 2026-09-25

### Added
- **`KeyProvenance` on `Task`:** where each key of a task's context came from (a command-line option and the configuration-file value it replaced, the `-c`/`--task` file, or the blueprint default), filled by `TaskFactory`. `tadah hpo` journals where `FORCE` and `STRESS` came from.
- Per-dataset energy and force RMSE derivatives (used by per-dataset HPO validation targets).
- `mlip::parallel_for` facade for the train/predict kernels; defaults to the previous OpenMP loop, and lets `tadah hpo` route the work onto its shared worker pool.
- `tadah refit --retarget --rhoform SIGNED|NONNEG|MONOTONE` (`RetargetOptions::rhoform`): under `NONNEG`/`MONOTONE` a file without a `RHOFORM` header gets `rhoform_bounds_line()` where `write_hpotarget` puts it and non-negative `AMPGRIDMB` boxes, so the result equals the writer's file for a potential in that form; a header that names another form is an error at its line. `validate_refit_mode_keys` refuses `RHOFORM` and `EMBF0` in a `--retarget` configuration (no effect on an hpotarget) and `RETARGET_RHOFORM` without `--retarget`; `run_refit_edit` applies `check_embf0_precedence` / `check_rhoform_precedence` to a key the configuration sets. Tests: `test_refit_retarget.cpp`, `test_refit_edit_mode.cpp`.
- `corner_context()` (`check_bounds.h`): the context `tadah analysis check_bounds` audits a corner in.
- **`tadah analysis dataset_stats` lists the structures whose cell is not symmetric** (max |C − Cᵀ| > 0), by 1-based index and label, with their count (`3 of 5 structures have a non-symmetric cell ...`; `0 of N ...` otherwise), on standard output at every log level. Only in these can a cell that an older Tadah stored transposed be told apart from a correct one (see the data-migration note under *Fixed*); nothing is guessed about any of them. Test: `test_dataset_stats_cell.cpp`.
- `NNTable::cutoff` (the cutoff a neighbour list was built for) and `NNTable::guard` (the rounding band above it in which the list may also hold pairs: 32 eps (G + 2)(cutoff + 2 max|r_i|), about 1e-13 relative for atoms near the cell); `DescriptorsCalc::neighbour_cutoff()`, the cutoff a structure's list must reach for that calculator.

### Changed
- **The stored stress is the Cauchy stress in eV/Å³, positive under tension, from every reader** (what the model predicts, what `pair_style tadah` gives LAMMPS as minus its pressure, and ASE's `get_stress`). The VASP OUTCAR and `vasprun.xml` readers stored VASP's pressure-signed tensor; they now negate it. **Datasets converted from VASP by Tadah 1.0.0 to 1.5.x, or by a 1.6.0 development build without this change, hold the opposite sign: re-convert them** (their energies change too, see the next entry). Such a build stores the OUTCAR `in kB` value times +6.241509074e-4, this one times −6.241509074e-4 (*Dataset Format* in the docs). CASTEP and LAMMPS-derived data, and data from ASE, already had this sign.
- **The VASP readers store the free energy F** (OUTCAR's ionic-step `free  energy   TOTEN`, the calculation-level `e_fr_energy` of `vasprun.xml`), the energy whose gradient the forces and the stress are, as the CASTEP readers do. OUTCAR stored the energy without entropy, `vasprun.xml` (VASP 5.4.4) energy(σ→0): up to 18.7 meV/atom off F in the test files, by an amount that varies by structure. Stored energies cannot be repaired in place; re-convert.
- **CASTEP `.md` stress: the kinetic term is removed exactly**, σ = S + (1/V)Σ m v⊗v with the frame's velocities and periodic-table masses, scaled to the frame's kinetic energy; a frame with a stress tensor (`<-- S`) whose kinetic energy is more than 1e-3 off those masses (a custom `SPECIES_MASS`) is refused (a frame without one needs no masses and is read). Before, k_B was applied twice and the correction subtracted from all nine entries, so nothing was removed (0.43 GPa of kinetic pressure in the 633 K test file).
- **LSCALE divides the stored stress by s³** (it was left unchanged on the assumption that the stress was an energy-unit virial). `Structure::get_virial_pressure()` returns −tr(σ)/3 in eV/Å³ (it returned tr/V/3, eV/Å⁶ with the opposite sign), and `get_pressure()` adds N k_B T / V to it. `StructureTransformation::scale()` leaves the stress unchanged (it multiplied it by factor²).
- **`tadah data dedup`** keeps the first of each set of equal structures and matches atoms one to one, in any order and through the periodic cell: `Structure::is_the_same` tries every lattice translation, of either structure's cell, that can bring a position within the threshold, and searches the matching with augmenting paths, so whether two structures are the same depends neither on the atom order, nor on how the cell is written, nor on which of the two is compared with which (which copy `data dedup` keeps is still the first in file order). Comparing a structure with a singular cell is an error (`std::invalid_argument`; `data dedup` names both structures by file and position), and so are a threshold not below λ/(2√3) ≈ 0.2887 λ, λ the shortest lattice vector, at which two images of a position could both match, and a cell written with so skewed a basis that more than 10⁶ translations would have to be tried to find λ (write it with a reduced basis); `--threshold` has no default and is required. Tadah 1.5.x compared positions directly, without the cell, and deduplicated structures with a singular cell; they are now refused.
- **A structure without a stress tensor is stored with stress weight 0** (`sweight`) by every DFT reader (OUTCAR, `vasprun.xml`, `.castep`, `.md`, `.geom`), with one INFO line per file, so that a `STRESS true` fit ignores its stress; it was stored with zero stress and weight 1, and the fit fitted zero stress (for example to `Mn.castep`, a fixed-cell run under 17.7 GPa). Likewise a `.castep` structure without forces (e.g. a cell relaxation with every ion fixed) gets force weight 0 (`fweight`). `tadah data balance --rescale` keeps a weight of 0 (it set it to 1 again).
- **The force and stress metrics leave out structures stored with weight 0** (MK's decision): `Analytics::calc_f_mae`/`calc_f_rmse`/`calc_f_r_sq` skip a structure with force weight 0 (`fweight`), `calc_s_mae`/`calc_s_rmse`/`calc_s_r_sq` one with stress weight 0 (`sweight`), and so do the `PC_FRMSE`/`PC_SRMSE` partials of `analytics_grad` (`counts_in_metric()`). Such a structure has no forces or stress tensor of its own (the readers store zeros in their place); the metrics compared the prediction with those zeros. A dataset in which every structure has that weight 0 is not measured (MK, 2026-10-06): its value is nan, the partials emit nothing for it (and the averaging `analytics_grad::frmse` and `srmse` differentiate the mean over the measured datasets), and `measured_datasets()`/`measured_mean()` let callers average the measured datasets; `require_metric_structures()` refuses only a set in which no dataset has the data, naming the files and the weight. `tadah predict -A` prints nan for such a dataset, a mean over the others and a note naming it, refuses before predicting when no dataset has the data (`-F` for the force metrics, `-S` for the stress metrics), and refuses a dataset that the filters (EFILTER, FFILTER) leave without structures, saying so. A weight of 0 set by hand to keep a structure out of a fit now keeps it out of these metrics too; the energy metrics are unchanged.
- **A dataset value that is not a finite number is refused**, naming the file, the structure and the text (`nan`, `inf`, `1e309`, `abc`; an atom line with fewer than the seven fields `Element px py pz fx fy fz`, or a non-number among them; a symbol that is not an element). Fields after the seventh are ignored, as before. A line of only whitespace (`\r` of a CRLF file included) separates structures like an empty one.
- **The OUTCAR reader skips the steps of VASP's machine-learned force field** (`ML_MODE = train`/`run`; blocks marked `ML`, never read) with one WARNING naming the file and the ionic steps, refuses an MD step that ends without its `free  energy   TOTEN` line, naming the file and the step, warns about a last MD step the file ends inside after its free energy and before its EKIN_LAT line (it is skipped, as before; a step cut off earlier, without its energy, is skipped without a warning), and labels each structure `Structure <n>` with n its ionic step (the stored count before; the same for a file without ML steps). An `in kB` line that cannot be read (VASP's `*****` overflow) gives the step stress weight 0 and a warning. The `vasprun.xml` refusals name the file and the calculation, and an `e_fr_energy` value that is not entirely a number is refused (1.5.x read `e_wo_entrp` instead, reported one it could not read and stored the calculation with energy 0, and read `12abc` as 12).
- **CASTEP `.md`/`.geom` frames:** a malformed frame is an error naming the file, the frame and the line (it was dropped silently); a last frame the file ends inside is skipped with one WARNING.
- **`M_KRR` potentials record the training `FORCE` and `STRESS`**, as `M_BLR`'s do: `M_KRR::get_param_file` no longer removes them (it still leaves out `ALPHA`, `BETA` and `DBFILE`), so `pot.tadah` and an HPO `best_pot.tadah` say what their fit used. `tadah predict` (its `-F`/`-S` decide) and `pair_style tadah` do not read them.
- **An error in a task file names the line of the file, and the file, in every section** (`Invalid value for key EMBF0 on line 6 of run.task: 'frei' (allowed: ZERO, FREE)`). `MLIPUserConfigParser` keeps each `GLOBAL` or `TASK` section's blank and comment lines and its first line number, and hands both to the key parser (`IUserConfigParser::parse(lines, first_line, source)`, CORE); without them the line was the value's index among the section's key lines. Test: `test_user_config_sections.cpp`.
- **Potentials of DM_REAM models always carry `EMBF0`** (`get_param_file` of M_BLR/M_KRR and `dumpPotFile` normalise the key: ZERO when absent, canonical spelling; a stray key is removed from potentials without a DM_REAM block).
- `tadah predict` (and the descriptor/pairwise analysis engines): a potential and a task configuration that set different `EMBF0` values are refused; a task value applies to a potential without the key (INFO).
- `tadah train`: a HINT when a DM_REAM model under `EMBF0 ZERO` is trained without BIAS and without ESHIFT (the model then has no free per-atom constant).
- `tadah refit`: reads `EMBF0` from the refit configuration (default ZERO); the self-test, curve and compare dumps use the zero-referenced table under ZERO and the log reports the removed table F(0); `REFIT_CONSTRAIN_F0 false` under ZERO warns (no effect). `refit --edit` logs the pot's mode (WARNING when the input has no `EMBF0` line). The hpotarget header notes the ESHIFT/BIAS requirement under ZERO.
- **Dataset files follow NUMERIC as significant digits, default 18 = exact.** `tadah data convert|merge|split|sample|dedup|balance` (`StructureDB::dump_to_file`) wrote NUMERIC fixed decimals: values below ~0.01 lost significant digits and values below 5e-19 became 0, so a rewritten dataset trained on slightly different targets and weights than the command computed (e.g. a `balance --rescale` eweight). Every number is now written with `%.{N}g` in `N+7` columns and reads back bit-identically; an explicit NUMERIC below 17 is honoured with a WARNING (`StructureDB::dataset_digits`). Files usually get shorter. The LAMMPS data and VASP POSCAR exports of `tadah data write` follow the same rule, masses included (`StructureDB::export_digits`); the CASTEP cell export keeps NUMERIC decimal places. The default precision of `dump_to_file` is 18 (was 12 decimals) and of `StructureWriter` 18 (was 10). Test: `test_dataset_precision.cpp`.
- **Pre-flight audit: no "critical hyperparameter RCUT2B/RCUTMB is fixed" warning for bump potentials under a hard cutoff.** `run_critical_optim_audit` already skipped knot channels (RCUT is derived from the largest knot); it now also skips `D2_Blip`/`D2_Blip5` pair channels and `DM_REAM` bump densities whose cutoff is discontinuous (`Cut_Dummy`, the refit default): there RCUT is the fitted truncation, every bump support ends at or before it, a larger value changes no prediction and a smaller one only trips the bump-support gate, and `tadah hpo` warns when `OPTIM RCUT*` is written anyway. Under a smooth cutoff the warning stays (the damping tail depends on RCUT). Test: `test_preflight_audit.cpp`.
- **hpotarget writer/`--retarget`: bump-channel OPTIM boxes are no longer capped.** `tadah hpo` now enforces the bump-support invariant `c + w/eta <= RCUT` per candidate (`BUMPGATE CANDIDATE`, its new default — violating combinations are rejected before training), so the writer emits CGRID/SGRID bounds at full symmetric width and `--retarget` stops re-applying the cap (`apply_bump_cap`/`BumpCapResult` removed). The parsed contract comment (`# RCUT2B bump-support contract: w = ...`) is kept — reworded — and still drives the seed-spill warning (a pot whose own bumps spill is rejected by hpo's startup SEED check) and the `--set` infeasible-corner warning; the ACTIVE-`OPTIM RCUT*` wasted-dimension note is softened to the new semantics (the sampled cutoff only reshapes the feasible region). Old capped files retarget fine: the centre-recovery rule for asymmetric (hi-capped) lines is unchanged, and retarget(fresh, same pct) remains byte-idempotent.
- Framework version `1.6.0`, read from CORE's `blueprint/blueprint_tadah.toml` after the Tadah dependencies are fetched, so the module reports the right version in every layout (sibling checkout or FetchContent). A missing blueprint is now a configure error instead of a silent `0.0.0`.
- Tests take Catch2 and its test discovery from cmake-tools (`tadah_setup_tests()`, `include(Catch)`); the vendored `tests/catch2/catch.hpp`, `tests/Catch.cmake` and `tests/CatchAddTests.cmake` are removed. Every discovered CTest entry now selects exactly its own test case and passes `--warn NoTests`, so an entry that matches no test case fails instead of passing.
- cmake-tools is fetched at `v1-dev` instead of `main`.
- The pre-flight audit hint for a critical hyperparameter that is fixed in the seed and absent from every `OPTIM` block names the cause: the seed value "misses the neighbour distances of the training data (e.g. a cutoff or radial grid that does not overlap the neighbour shells)". It said "(BASINS-style)", after an experimental HPO strategy that the user documentation never described and that is removed in 1.6.0.
- The documentation of `classify_dataset` states its decision rules instead of pointing to a BASINS investigation note that is not in the repository.
- The two `NNFinder: real CH4 phase-I structure` tests are reported by CTest as Skipped, not Passed, when their optional database is absent (`TADAH_TEST_PHASEI_DB` unset and no `ch4_phasei_S_U67.tadahdb` in the working directory): they call `TADAH_SKIP` (cmake-tools' TADAH-SKIP marker) instead of returning after a warning. A database that `TADAH_TEST_PHASEI_DB` names and that cannot be opened fails them.
- **A `DIMER` potential whose descriptors name specific element pairs is refused when it is loaded** (`tadah train`, `tadah predict`, and every other user of `DescriptorsCalc`). `calc_dimer` evaluates every atom as Z=1, whatever its element (with the pair weight of Z=1, not the `WATOM` weight of the element), so a `TYPE2B`/`TYPEMB` declared for `N N` applied to no pair it sees and the model predicted from zero descriptors without a word (`tadah predict` gave 0 eV for the published Tadah!N2 potential with `N N` pairs; -0.00184 eV/atom with its `* *`). Every `DescriptorsCalc` constructor now calls `models::require_dimer_element_pairs()` (MODELS 1.6.0): `DIMER evaluates every atom as Z=1; declare TYPE2B/TYPEMB with * * element pairs`. Test: `test_descriptors_calc_dimer.cpp`.
- The README badges and links and the pointers to the umbrella's community files (`CITATION.md`, `CONTRIBUTING.md`, …) point to the `v1-dev` line: GitLab `v1-dev`, `https://tadah.readthedocs.io/v1-dev/`. They pointed to `develop`.
- **BREAKING — DM_REAM potentials must declare their density form, `RHOFORM SIGNED | NONNEG | MONOTONE`** (see Tadah.MODELS). The potential writers (`get_param_file` of M_BLR/M_KRR, `TrainEngine::dumpPotFile`) call `normalise_rhoform_key`: a DM_REAM model without the key throws before the file is opened (nothing is inserted), the value is written in upper case, and a stray key is removed from potentials without a DM_REAM block. `tadah predict`, `tadah analysis descriptor` and `tadah properties pairwise` call `check_rhoform_precedence` before merging the task over the potential: a DM_REAM potential without `RHOFORM` is refused even when the task sets the key (the form belongs to the potential), and a task value that differs from the potential's is refused. **Migration:** add `RHOFORM SIGNED` to a DM_REAM potential or configuration written before tadah 1.6.0 (bit-identical). Tests: `test_rhoform_pot_key.cpp`.
- **`tadah refit` fits in a declared density form.** `RHOFORM` is required in the refit configuration (`validate()` and `run()`, before the table is read: "tadah refit configuration: DM_REAM: RHOFORM is required: ..."); `EAMRefitConfig::rho_form` carries it, and the log states it (`tadah refit: RHOFORM <form>: ...`; the dense optimisation log header gains `rhoform=<form>`). The form x `REFIT_BASIS` x `REFIT_MODE` matrix is checked before any fitting: `MONOTONE` with `Knot3`/`Knot5`/`KnotMix` is an error that names a defaulted compact basis as such ("tadah refit: RHOFORM MONOTONE is not defined for REFIT_BASIS Knot5 (the REFIT_MODE compact default, a one-sided knot family): use a bump basis (Blip, Blip5) or RHOFORM NONNEG ..."), `MONOTONE` needs a whitelisted cutoff (the refit writes Cut_Dummy), and `NONNEG` with a knot family in compact mode reports that a non-negative knot density is locked to non-increasing convex shapes, so a table with a concave core is fitted poorly: a HINT when `REFIT_BASIS` names the family, a WARNING recommending `REFIT_BASIS Blip5` when the knot basis is the compact default. Every form fits in both modes; without the HPO build `REFIT_MODE compact` falls back to the dense path in the declared form. `SIGNED` writes the potential it wrote before the key existed, plus the `RHOFORM SIGNED` line. Tests: `test_refit_engine.cpp`.
- **`refit --edit` edits in the potential's form**: the input must declare `RHOFORM` (`parse_pot_view`), the log states the form (`tadah refit --edit: RHOFORM <form>: ...`), `--remove` keeps every density amplitude >= 0 under `NONNEG`/`MONOTONE` (bounded compensation, see Tadah.MODELS), and the edited potential keeps the key. Tests: `test_refit_edit_mode.cpp`.
- **hpotarget writer and `--retarget`: non-negative `AMPGRIDMB` boxes under `NONNEG`/`MONOTONE`.** The writer requires `RHOFORM` on a DM_REAM potential, applies `models::optim_key_lower_bound` on top of the static key table (`hpotarget_group_specs()`, unchanged): lo = max(0, v - d), so a zero amplitude gets [0, d]; and it records the form in a parsed header line, `# RHOFORM <form>: AMPGRIDMB bounds are non-negative (lo = max(0, v - d))` (`rhoform_bounds_line`), because `--retarget` never sees the potential. `--retarget` reads that line (`RetargetReport::rhoform`): a line clamped at lo = 0 is recovered from its upper bound without a warning, every rewrite keeps lo >= 0, the log says so, and `--set` with an `AMPGRIDMB` lo < 0 is refused. A `SIGNED` file is written and retargeted exactly as before. Tests: `test_refit_retarget.cpp` (including the fixed-point checks).
- **A left-handed cell has a positive volume.** `Structure::get_volume()` and `StructureProperties::getVolume()` return |a0 · (a1 × a2)|: CASTEP accepts a left-handed basis, and a POSCAR can hold one (the `md_stress.castep` fixture has det = −240.27 Å³, CASTEP prints 240.27), and the signed value flipped the sign of every stress design-matrix row and stress prediction of such a structure (its stress targets were not flipped), made `get_density()` negative and `StructureProperties::getDensity()` 0, made `scaleToVolume` throw, and kept the native relaxer's Iso mode from converging. Cells are stored as read, in either handedness. Test: `test_cell_handedness.cpp`.
- **`StructureTransformation` maps the lattice with the atoms** (row i of `Structure::cell` is lattice vector a_i). `rotate` and `shear` set cell' = cell·Mᵀ (they set M·cell, the column formula, so the atoms of a non-symmetric cell moved to other fractional coordinates); `rotate` also rotates the forces. `mirrorPlane` and `mirrorHkl` reflect the cell (cell' = cell·Mᵀ; the result is left-handed) and the forces too; they reflected only the positions. `mirrorOrigin` inverts the forces with the positions (the cell is unchanged: −aᵢ span the same lattice). `replicate` builds the supercell along the rows (nx a0, ny a1, nz a2, copies at r + ix a0 + iy a1 + iz a2; it scaled only the diagonal of the cell and shifted the copies along its columns), multiplies the energy by nx·ny·nz, clears the neighbour list, and refuses a factor below 1 (`std::invalid_argument`; it was clamped to 1). HPO's `cohesive_energy` observable replicates a cubic cell, where nothing changes. Tests: `test_structure_transformations_cell.cpp`.
- **The LAMMPS and VASP exports (`tadah data write -f LAMMPS|VASP`) write a right-handed box**, as LAMMPS and VASP require: a left-handed cell becomes (a0, a1, −a2), a basis of the same lattice — in the LAMMPS file with `abc origin` a2, so the box is the same parallelepiped, every atom stays inside it and each lattice direction keeps its boundary flag; the POSCAR keeps the Cartesian positions. A singular cell is refused before the file is opened, naming the structure. Tests: `test_lammps_writer_cell.cpp`, `test_poscar_writer_cell.cpp`; HPO `test_lammps_export_readback.cpp` reads the LAMMPS file back into LAMMPS under `boundary p p p` and `p p f`.
- **`AflowReader::parseAflowJson` is public**, so an AFLOW entry can be parsed without a network query.
- **Consumers of a neighbour list refuse one that does not cover their cutoff** (for a list the native relaxer's cache keeps after the atoms or the cell moved, the check uses the build cutoff; `nn_cache::is_fresh` guarantees the list for rcut = cutoff − skin). `DescriptorsCalc` (`calc`, `calc_rho`, and `calc(StructureDB)` before its loop), the dPhi/dtheta walkers and `build_dm_rho_cache` (before their loops) throw `std::logic_error`, naming the structure and both cutoffs, for a missing list or one built with a cutoff below the model's; before, a short list was used silently. `Structure::get_nn_iindex` throws `std::logic_error` when atom j has no reverse entry (it returned `idx[j].size()`, an index past the list; never for a table NNFinder built). Tests: `test_nn_list_guard.cpp`, `test_structure.cpp`.
- **`nn_cache::is_fresh` keeps a list exactly while it provably holds every pair within rc = cutoff − skin**: with M = A⁻¹A₀ (current and cached cell rows), `(rc + δ)·min(√(‖M‖₁‖M‖∞), 1 + ‖M − I‖_F) + 2·maxᵢ|rᵢM − r₀ᵢ| + τ ≤ cutoff` (δ, τ rounding bounds). For an unchanged cell this is LAMMPS' skin/2 test; a cell change now counts what it moves the images, so a uniform 10% expansion keeps the list (the box-corner rule dropped it) and a thin cell compressed along one axis drops it (the corner rule kept it while 18 pairs were missing). The cutoff is read from the list (`NNTable::cutoff`); a list whose cutoff does not exceed the skin is refused (`std::logic_error`). `NativeRelaxer` caches only when `nn_skin > 0`, as documented. Tests: `test_nn_cache.cpp` (the test `nn_cache: box expansion erodes effective skin (corner shrink)` is now `nn_cache: a cell change keeps the list only while it provably covers the cutoff`), `test_native_relaxer.cpp`.
- **`NNFinder` refuses invalid input** with `std::invalid_argument`: a cutoff that is not finite and positive, a non-finite cell entry or position, a cell vector shorter than 2^-200 Å or longer than 2^200 Å (outside that range the cell geometry under- or overflows), a singular (or numerically singular) cell, an atom more than 2^31 cells from the origin, and positions whose rounding bound exceeds an image cell (an atom far out in a cell near the conditioning limit). A structure without atoms gets an empty list without its cell being examined. `NNFinder::calc(StructureDB)` rethrows the lowest-numbered failing structure's error with its type, prefixed `NNFinder: structure <i> of <N> ('<label>'): `. `NNFinder::check_box` compares the heights of the (reduced) cell with the cutoff, and refuses an invalid cell; it compared the edge lengths, which a tilted cell can exceed while a height is below the cutoff. The image cap (10⁴ image cells) is counted from the heights, without rounding margins, so it does not depend on where the atoms are stored: a cube is refused once the cutoff reaches 10 edges. Before, it was refused only beyond 11 edges; in between, cubes with more than one atom could get wrong lists, and one-atom cubes, whose lists were right, are now refused too. Two atoms at the same position are listed as neighbours at distance 0, as before (consumers divide by the distance; such a structure is not physical). Tests: `test_nn_finder_exact.cpp`, `test_nn_finder_gaps.cpp` (the test `NNFinder: degenerate near-zero cell triggers kMaxTotalShifts throw` is now `NNFinder: a degenerate near-zero cell hits the image-cell cap`).

Next to a loop that forms a group, or a readable Hall symbol, such a symbol gives the WARNING below. A number alone gives a WARNING naming the setting used when the cell could be in another ITA setting of the group (another origin choice, or another choice of axes that fits the cell: 227, 14, 65, 73, P 21/m (11) in a cell with all angles 90); P 1, P -1, I 4/m m m, the R groups (whose hexagonal and rhombohedral axes the cell tells apart), P 21/m in a cell with beta ≠ 90 and the extra origins gemmi lists from CCP4 (22, 23, 94 and 197 then give none; 18, 20 and 21 warn for their other axes) give none. - **Potential files are written losslessly.** `TrainEngine::dumpPotFile` (train, `refit`, `refit --edit`) writes through `Context::write_potential`: every non-integer number with NUMERIC significant digits, default 18, so a potential reloaded from pot.tadah is bit-identical to the one in memory. NUMERIC is never written into the file; an explicit NUMERIC below 17 is honoured with a WARNING. `tadah refit` now honours NUMERIC from its configuration (it was ignored). `refit --edit` also honours a NUMERIC carried by the edited potential -- every 1.5.0 `tadah hpo` potential has `NUMERIC 12`; delete that line -- with a WARNING naming its source, and no longer promises an identical prediction when NUMERIC < 17. Tests: `test_dump_pot_file.cpp`, `test_refit_engine.cpp`, `test_refit_edit_mode.cpp`.
- **LSCALE / ESHIFT are stamped into pot.tadah exactly.** They had 6 significant digits, so predict and HPO applied a slightly different transform than training; newly trained potentials may differ from older ones by up to ~1e-5 eV/atom. Test: `test_load_transforms.cpp`.
- Readers accept subnormal values (`core::to_double`): FIXWEIGHT, the energy-only line of a dataset structure, `refit --retarget` bounds, hpotarget contracts, VASP POSCAR coordinates and CASTEP cell numbers. A FIXWEIGHT written as `1e-310` failed with "FIXWEIGHT entry is not a number", and a POSCAR exported by `tadah data write` with a subnormal coordinate failed to load. Tests: `test_weight_provisioning.cpp`, `test_dataset_precision.cpp`.
- **`Structure::save` writes the z force, and every double exactly.** The z force column held `force(1)` (the y component); weights and energy had 6 significant digits, and cell, stress, positions and forces 6 decimals. Every double now has 17 significant digits, so `save()` -> `read()` round-trips bit-exactly; `save(path)` throws when the file cannot be opened or written, the caller's stream format is restored, and a one-letter symbol no longer writes a NUL byte. `Structure::save` has no CLI caller (public API only). Test: `test_structure.cpp`.
- **`--retarget` recovers lower-bound-clamped lines with their own group's percentage.** A line whose lower bound was clamped (the width channels, RCUT scalars, and now non-negative amplitudes) was recovered from its upper bound with the file header's percentage, while a per-key retarget (`--pct 5 SGRIDMB=50`) rewrites only that group's `# KEY  (+-X%` comment; repeating such a retarget moved the recovered centres, so the file was not a fixed point. The group comment's percentage is used now (the header's for groups without one).
- `refit --retarget`: a per-key percentage on an `RCUT2B`/`RCUTMB` scalar line is recorded in a group comment above the line (`# RCUT2B  (+-50%, 1 params)`, removed again at the global percentage), so `RCUT2B=50` run twice is byte-identical; the second run recovered the centre with the file header's percentage. `--pct`/`--set` numbers are read with `core::parse_decimal_normal` (the hpotarget grammar) instead of `core::to_double`, which took `5x`, `0x10`, `inf`, `nan` and subnormals. `--pct KEY=N` for a key without an `OPTIM` line is an error. A `--set` needs finite bounds, `lo < hi`, and a `lo` the density form's rule admits (`optim_low_bound_rule(...)->admits`: NaN is refused). The `RHOFORM` header error names its line. Tests: `test_refit_retarget.cpp` (with the missing fail-before test of the per-group percentage, `SGRID2B=50` run twice).
- `check_bounds_at_corners` requires `RHOFORM` for a DM_REAM seed (`require_rhoform`; `stored_rhoform` let a seed without it pass without the density rules), takes the seed's basis for the rules (`optim_rule_basis`: the Gaussian `SGRIDMB` rule under `NONNEG`), and builds each corner with `corner_context`, which sets only the bound's entry: a vector key was replaced by `arg_pos + 1` copies of the corner value (`(1)` by one), and two bounds on one key overwrote each other. Tests: `test_check_bounds.cpp`.
- `check_bounds_at_corners` audits every corner against `models::optim_low_bound_rule(key, seed)`, the rule `tadah hpo` refuses a box by: besides the density-form rules, every radial bump width > 0 in every form (`SGRIDMB` of a DM_REAM `Blip`/`Blip5` density, `SGRID2B` of a `D2_Blip`/`D2_Blip5` pair term; owner decision 2026-09-29), so a width box reaching 0 or below fails its low corners (a `NONNEG` `Blip5` `SGRIDMB` box from -0.5 passed). A finding names what sets the rule (`RHOFORM NONNEG requires ...`, `the D2_Blip5 pair basis requires every SGRID2B width > 0 ...`). Tests: `test_check_bounds.cpp`.
- `TrainEngine::dumpPotFile` and `write_hpotarget` throw, naming the path, when the output cannot be opened or written; they logged an ERROR / a WARNING and returned, so `tadah train -o no_such_dir/pot.tadah` exited 0. Test: `test_dump_pot_file.cpp`.
- `tadah analysis bfunc` applies `check_embf0_precedence` and `check_rhoform_precedence` to the potential and the task before merging them, as predict and analysis descriptor do. Test: `test_rhoform_pot_key.cpp`.

- **The CIF reader (and the COD reader, which uses it) stores lattice vector aᵢ as cell row i.** It copied gemmi's orthogonalisation matrix, whose columns are the lattice vectors, untransposed: every non-orthogonal CIF/COD structure (hexagonal, trigonal, monoclinic, triclinic) had a transposed cell while its atoms were placed correctly (hcp Mg got a 2.78 Å neighbour instead of 3.20 Å). `tadah predict -s`, `tadah data print|write -s` and the analysis tasks used that cell, and `data write` exported it to VASP, LAMMPS and CASTEP files. Test: `test_structure_readers_cell.cpp`.
- **The AFLOW reader places the atoms from `positions_fractional`.** It built the cell from `geometry` (a along x, b in the xy plane) but took the atoms from `positions_cartesian`, which AFLOW gives in its own frame, so a multi-atom entry did not fit its cell (rock-salt NaCl: a 1.91 Å Na–Cl distance instead of 2.82 Å). An entry without `geometry` (it became a 1 Å cube) or without `positions_fractional` is refused, and so are an entry whose species, composition counts and positions do not match (the documented fallback labelled the atoms `X`, which is no element, so it threw "Unknown symbol: X"; two species with one count read past the counts, and one species with two counts dropped a site), a site without exactly three numbers (a missing one became 0), and angles no cell has (they were clamped to a flat cell). Test: `test_structure_readers_cell.cpp`.
- **POSCAR reader: VASP's scaling rules.** Cartesian coordinates are multiplied by the scaling factor, as the lattice is (they were read unscaled, so a Cartesian POSCAR with a factor other than 1 put the atoms in the wrong place); a negative factor is the cell volume (it inverted and inflated the cell); three factors scale the x, y and z components of the lattice vectors (and of Cartesian coordinates); a zero factor, two factors, a non-positive one of three, or no number is refused. The coordinate mode and the Selective dynamics line are recognised by their first character as VASP does (`C`/`K` for Cartesian, `S` for Selective dynamics; `K`, `Kartesian` and `Sel dyn` were missed, and `Direct coordinates (not Cartesian)` was read as Cartesian). A file without the element-symbol line (the VASP 4 layout) is refused with a message saying so (it failed with "Unknown symbol: X"), and so is a symbol line and count line of different lengths (it read past the symbols). Test: `test_structure_readers_cell.cpp`.
- **CASTEP `.cell` reader: units and block order.** The optional unit line of `LATTICE_CART`, `LATTICE_ABC` and `POSITIONS_ABS` is applied (`ang`, `bohr`/`a0`, `nm`, `cm`, `m`, `pm`, any case; it was skipped, so a cell in bohr was read 1.89× too small); `POSITIONS_FRAC` is converted after the whole file is read, so the blocks may come in any order (positions before the lattice all landed at the origin). Text after `!`, `#` or `;` is a comment on any line, as in CASTEP (a commented unit line was taken for data, and a header such as `%BLOCK POSITIONS_FRAC!sites` dropped its atoms). A file without a lattice block or a positions block (it gave a structure with no atoms), a `LATTICE_CART` without exactly three vectors (a fourth wrote past the cell), an incomplete `LATTICE_ABC`, a singular lattice, an unknown unit and a positions block without atoms are refused. Test: `test_dataset_readers_cell.cpp`.
- **Data migration: datasets converted by an older Tadah may hold a wrong cell.** Row i of the cell block is lattice vector aᵢ (`Structure::cell`, *Dataset Format*). Only structures with a non-symmetric cell can be affected; `tadah analysis dataset_stats` lists them. Re-convert them from their source files if they were converted: (1) before 1.3.0-beta.1 (MLIP `c6d457c`, 2026-05-07) from a VASP OUTCAR or a CASTEP `.castep`, `.md` or `.geom` file — the cell was stored transposed (the positions are right: transposing the 3×3 cell block repairs it); (2) before 1.3.0-beta.1 from a vasprun.xml — the cell is right, the positions are not (r_new = cellᵀ·cell⁻¹·r_old repairs them). Structure files that `tadah data write -s` exported (VASP, LAMMPS, CASTEP) from a non-orthogonal CIF or COD entry before 1.6.0 hold a transposed cell (see above): export them again. Potentials and `tadah hpo` results fitted to affected structures need to be regenerated. The 1.3.0-beta.1 change was not recorded in this changelog.
- **`NNFinder` finds every periodic image of any cell.** Its image bound came from the lattice translations shorter than the cutoff instead of the cell heights, so a cell thinner than the cutoff in some direction lost images (a 2-atom bcc cell with a = 3.41 Å at a 10 Å cutoff listed 168 of each atom's 180 neighbours, and the neighbour vectors no longer summed to zero: a perfect crystal got forces); atoms outside the cell and cells whose matrix is not symmetric were binned with wrong fractional coordinates (a sheared cell lost 6 of 80 images, an unwrapped cube 28 of 38 pairs); a tilted cell with every edge above the cutoff but a height below it took the path meant for thick cells; and a tolerance merge of close images made thin-cell tables asymmetric. One search now serves every cell: the lattice basis is reduced (an integer unimodular change of basis, so a skewed description of a benign lattice costs nothing), the atoms go into a cell list over their wrapped fractional coordinates sized by the cell heights, and each pair is tested once with the distance computed as consumers compute it, keeping pairs below cutoff + `NNTable::guard` so every pair a consumer computes inside the cutoff is listed. Shifts are integer triples relative to the stored positions (never changed), each atom's entries are sorted by (j, shift), and the table is symmetric. Thick cells with wrapped atoms get the same pairs within the cutoff in the same order as before (bit-identical results), plus any pair within `NNTable::guard` above the cutoff (a lattice shell exactly at it), which consumers ignore; other structures change — retrain potentials fitted to them. `tadah predict` now agrees with `pair_style tadah`. Tests: `test_nn_finder_exact.cpp` (against the brute-force oracle `tests/nn_oracle.h`), `test_nn_replication_invariance.cpp`.
- **A neighbour-cache hit after a cell change returned the image displacements of the old cell** (`nn_cache::is_fresh` handed back the cached table unchanged): the native relaxer's Iso forces were off by 0.04–0.49 eV/Å and HPO's cohesive-energy observable's E_coh by 0.06–0.08 eV/atom in the tests' setups. A hit with a changed cell now gets a copy of the table with the displacements of the current cell (the same table while the cell is bitwise unchanged). Tests: `test_nn_cache.cpp`, `test_native_relaxer.cpp`.
- **`compute_data_stats` (`tadah analysis dataset_stats`, the pre-flight audit)** rebuilds a structure's neighbour list when it was built with a smaller cutoff than the audit's (it counted from the short list), reports a structure NNFinder refuses as an exception naming it (it called `std::terminate` from its OpenMP loop), and counts neighbours strictly inside its cutoff, as the model does, so the counts stay the same now that a list may hold pairs within `NNTable::guard` above its cutoff (simple cubic a = 2.5 at 5 Å: 26 neighbours, not the 32 of the list). Test: `test_data_stats_compute.cpp`.
- `NNFinder::calc(StructureDB)` called `std::terminate` when a structure's search threw inside its OpenMP loop (the image cap on a degenerate cell); it now rethrows the error naming the structure.

## [1.4.0] — 2026-07-14

### Added
- **`--retarget --rcut2b <r> / --rcutmb <r>`**: declare a bump channel's fixed cutoff in the same run — the file's `OPTIM RCUT*` reference line is recentred on `r`, stray ACTIVE `OPTIM RCUT*` lines are commented out with a warning (searching RCUT on a gated bump channel is a wasted dimension), and the rewritten CGRID/SGRID boxes are truncated to `c + w/eta <= r`. Replaces the two-step `--set 'RCUT2B(1)=lo,hi'` + `--pct` dance after manually raising a pot's cutoff.

### Changed
- **hpotarget writer: bump channels under a hard (Cut_Dummy) cutoff get gate-compliant OPTIM boxes.** Per blip, the emitted CGRID upper / SGRID lower bounds are capped (directionally quantized, so the cap is exact on the bound grid) to the bump-support invariant `c_hi + w/eta_lo <= RCUT` that `tadah hpo` now hard-errors on, and a parsed contract comment (`# RCUT2B bump-support contract: w = ...`) records the half-width for `--retarget`. A pot whose own bump spills is emitted uncapped with a warning (the repair tool `refit --edit remove` also writes an hpotarget, so the writer never throws); knot/Gaussian/FIXWEIGHT emissions are byte-identical to before.
- **`--retarget` understands the bump-support contract**: recovers the centre of a hi-capped CGRID line from its LOWER bound (mirror of the existing lo-clamped SGRID repair), re-applies the cap after every rewrite (fresh(pct) -> retarget(pct) stays byte-identical; any retargeted file is byte-stable), and lets `--set` win with a warning when it violates the contract corner.
- `--retarget`: with duplicate or ACTIVE `OPTIM RCUT*` lines the bump-support cap now binds against the smallest reachable cutoff (active line -> its rewritten LOW bound, commented -> centre) and warns, instead of trusting whichever line comes first in the file.
- `refit --edit --add` passes the pot's cutoff kind to `potedit::add_basis`: a bump support crossing rcut is a hard error for Cut_Dummy pots (with the minimal `--eta` in the message), a warning for smooth cutoffs.
