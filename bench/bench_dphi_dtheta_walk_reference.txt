# Notes on the numbers above:
# - combined vs cached on this tiny config: cache trims ~12% off the
#   per-call walk time (0.063 → 0.056 ms). The cache build (0.008 ms)
#   amortises across all 29 θ in the live loop: 0.008 ms / 29 = 0.0003 ms
#   per θ overhead.
# - full_loop_emulation per_theta_median is 0.061 ms, close to the
#   cached_dm_mblip walk_median (0.056 ms). The small difference
#   reflects the palette of θ keys (mix of RCUTMB, CEMBFUNC, SEMBFUNC,
#   WATOM, CGRIDMB, SGRIDMB) — not all kernel branches are equally
#   expensive.
# - These per-θ times are 4-5 orders of magnitude smaller than the
#   per-θ wall of a live production blip6 run (~2.4 s). The live
#   config has n_train=1325 structs (vs 10 here) and n_atoms ~50-100
#   per struct (vs 4 here), plus a larger n_cols (12 vs 6). The bench
#   is a microbench — its value is catching kernel-level regressions,
#   not predicting live wall time.
